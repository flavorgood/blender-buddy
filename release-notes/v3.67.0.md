# Blender Buddy v3.67.0 — animation's sixtieth piece: moving diagonally

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release. The
public download still serves v3.20.0.

**Make it move diagonally** sits under "Learn by doing" beside the
modeling, sculpting and first fifty-nine animation
pieces — Buddy's sixtieth animation piece, teaching
moving diagonally, in four steps:

1. **Pick the thing that will move diagonally** — one thing that will
   travel forward and sideways together.
2. **Remember where it starts, on the ground** — a place
   memory at frame 1, location (0, 0, 1).
3. **Move it diagonally forward and sideways and keep it there** —
   place (1.5, 1.5, 1) remembered at frame 24, and
   place (3, 3, 1) remembered at frame 48, on the
   ground the whole way.
4. **Watch it move diagonally, then save** — played across the
   span, and the file saved with the place memories
   in it.

The teaching point is that a diagonal is both travels
together: a slide travels sideways only and a forward
move travels forward only — a diagonal goes both ways
at once, staying on the ground, reading places
(0, 0, 1) / (1.5, 1.5, 1) / (3, 3, 1) at frames
1/24/48 in the reference build ((2.5375, 2.5375, 1) partway across at frame 36). The checks sample the real evaluated place
across the span: the span must run at least 20 frames,
the forward travel must land between 2.2 and 3.8, the sideways travel must land between 2.2 and 3.8, no sampled place may sit more than 0.35 above or below the start height, and the
end height must sit within 0.35 of the start height. A probe on Blender 5.3.0 and 4.2.5
before building showed the place memories on the
ground at frame 1, halfway forward and halfway across
at frame 24 and far ahead and far across at frame 48 read back (span 47, forward
3.0, sideways 3.0, peak 0.0, trough 0.0, end deviation 0.0 in the probe); a slide read forward 0.0,
a forward-only move read sideways 0.0, a leap read peak 2.0, a small diagonal read forward 1.0 with sideways 1.0, a diagonal that returned read forward 0.0 with sideways 0.0, and a diagonal up in the air
read peak 2.0 with end deviation 2.0 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
place alone does not prove the diagonal, a slide does not
prove it, a forward-only move does not prove it, a leap does not prove it, a small diagonal does not prove it, and a diagonal that returns does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.67.0 source: the flows battery (all sixty-eight
flows plus the anim_diagonal negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_diagonal_final.png — the
reference build's red thing at frame 24, mid-diagonal
at (1.5, 1.5, 1), on the ground.
