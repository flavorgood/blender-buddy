# Blender Buddy v3.85.0 — animation's seventy-eighth piece: leaping the other way

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release. The
public download still serves v3.20.0.

**Make it leap the other way** sits under "Learn by doing" beside the
modeling, sculpting and first seventy-seven animation
pieces — Buddy's seventy-eighth animation piece, teaching
leaping the other way, in four steps:

1. **Pick the thing that will leap the other way** — one thing that will
   leave the ground, travel far the other way, and land far the other way.
2. **Remember where it starts, down on the ground** — a place
   memory at frame 1, location (0, 0, 1), down on the ground.
3. **Leap it up and the other way and land it far the other way** —
   mid-leap place (-1.5, 0, 3) remembered up in the air at frame 24,
   landing place (-3, 0, 1)
   remembered far the other way on the ground at frame 48.
4. **Watch it leap the other way, then save** — played across the
   span, and the file saved with the place memories
   in it.

The teaching point is that the direction a leap travels is part of the leap:
the leap piece's checker read the signed forward displacement — the end place's X minus the start place's X — between 2.2 and 3.8, so it could not pass the other way, and a first-way leap cannot pass this piece either — this piece's measure reads the same signed displacement and requires it between -3.8 and -2.2, so the first way reads signed travel +3.0 while the other way reads -3.0 with the same span, peak, ends gap and sideways drift, reading places
(0, 0, 1) / (-1.5, 0, 3) / (-3, 0, 1) at frames
1/24/48 in the reference build, and (-2.5375, 0, 2.0) partway down at frame 36. The checks sample the real evaluated place
across the span: the span must run at least 20 frames,
the signed travel must land between -3.8 and -2.2, the peak height must clear at least 1.2 above the start height, the landing height must sit within 0.35 of the start height, and the sideways drift must stay within 0.5. A probe on Blender 5.3.0 and 4.2.5
before building showed the other-way reference read span 47, forward -3.0, peak 2.0, ends 0.0, sideways 0.0; a first-way leap read forward +3.0 with the same span, peak, ends and sideways,
a slide the other way read peak 0.0, a bounce in place read forward 0.0 with peak 2.5, a glide-like travel the other way read ends gap 1.0, a small leap the other way read forward -1.0 with peak 0.4, a leap the other way that returned read forward 0.0, and a diagonal leap the other way read sideways 1.5 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
place alone does not prove the leap the other way, a first-way leap does not
prove it, a slide the other way does not prove it, a bounce in place does not prove it, a small leap the other way does not prove it, and a leap the other way that returns does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.85.0 source: the flows battery (all eighty-six
flows plus the anim_otherleap negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_otherleap_final.png — the
reference build's red thing at frame 24, up in the air mid-leap the other way
at (-1.5, 0, 3), halfway across the other way.
