# Blender Buddy v3.56.0 — animation's forty-ninth piece: widening

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it widen** sits under "Learn by doing" beside the
modeling, sculpting and first forty-eight animation
pieces — Buddy's forty-ninth animation piece, teaching
widening, in four steps:

1. **Pick the thing that will widen** — one thing that will
   spread out sideways and stay wide.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Widen it and keep it wide** —
   sides out to 2.0 (X and Y scale 2.0) remembered at frame 24, i.e. (2, 2, 1), and
   the same widened size remembered again at frame 48, height
   staying at 1.0 the whole way.
4. **Watch it widen, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a widening is the spreading
and the staying and the unchanged height together: the crouch and stand-up pieces
changed a thing's height only while its sides stayed at their own size — a widening
spreads the sides only, keeps them spread, and leaves the height at its own height, reading sizes
(1, 1, 1) / (2, 2, 1) / (2, 2, 1) at frames
1/24/48 in the reference build ((2, 2, 1) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end side ratios (X and Y) must each land between 1.7 and 2.3, the end height ratio must land between 0.8 and 1.2, the
sampled height ratio must never fall below 0.65 or rise above 1.35, and the
sampled side ratios must never rise above 2.35. A probe on Blender 5.3.0 and 4.2.5
before building showed the size memories at
(1, 1, 1), (2, 2, 1) and (2, 2, 1) across frames
1/24/48 read back and interpolate identically on both
versions (span 47, end X 2.0, end Y 2.0, end Z
1.0, lowest Z 1.0, highest Z 1.0, highest side 2.0 in the probe); a grow read end X 2.5 with end Z 2.5 and highest Z 2.5,
a shrink read end sides 0.4 and 0.4, a squash read end sides 1.0 and 1.0 with lowest Z 0.4, a small widen read end sides 1.3 and 1.3, a widen that returned
read end sides 1.0 and 1.0, a stretch that raised the height read end Z 2.5 with highest Z 2.5, and a stretch along one side read end X 2.5 with highest side 2.5 — all failing the bar.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the widening, a grow does not
prove it, a shrink does not prove it, a squash does not prove it, a small widen does not
prove it, a widen that returns does not prove it, and a stretch does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.56.0 source: the flows battery (all fifty-seven
flows plus the anim_widen negatives), the interface
battery, and the plain-layer and search batteries all
pass. Proof picture: demo/anim_widen_final.png — the
reference build's red thing at frame 36, widened
to twice its width with its height unchanged, on the
ground.
