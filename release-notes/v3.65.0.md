# Blender Buddy v3.65.0 — animation's fifty-eighth piece: diving

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it dive** sits under "Learn by doing" beside the
modeling, sculpting and first fifty-seven animation
pieces — Buddy's fifty-eighth animation piece, teaching
diving, in four steps:

1. **Pick the thing that will dive** — one thing that will
   fall far forward from up high and land far ahead.
2. **Remember where it starts, up high** — a place
   memory at frame 1, location (0, 0, 3).
3. **Dive it down and forward and land it far ahead** —
   mid-dive place (1.5, 0, 2) remembered at frame 24, and
   landing place (3, 0, 1) remembered at frame 48, never
   travelling sideways and never rising first the whole way.
4. **Watch it dive, then save** — played across the
   span, and the file saved with the place memories
   in it.

The teaching point is that a dive is the starting up
high, the far forward fall and the landing on the ground
together: the leap piece rose first and landed back at
its starting height, and the glide piece travelled
forward while staying up high — a dive only falls, from
up high, far ahead, down to the ground, reading places
(0, 0, 3) / (1.5, 0, 2) / (3, 0, 1) at frames
1/24/48 in the reference build ((2.5375, 0, 1.3083) partway down at frame 36). The checks sample the real evaluated place
across the span: the span must run at least 20 frames,
the forward travel must land between 2.2 and 3.8, the drop must land between 1.7 and 2.3, no sampled place may sit more than 0.35 above the start height, the
landing height must sit within 0.35 of the ground centre 1.0, and the
sideways drift must stay within 0.5. A probe on Blender 5.3.0 and 4.2.5
before building showed the place memories at
(0, 0, 3), (1.5, 0, 2) and (3, 0, 1) across frames
1/24/48 read back (span 47, forward 3.0, drop
2.0, peak 0.0, end deviation 0.0, sideways 0.0 in the probe); a leap read drop 0.0 with peak 2.0,
a glide read drop 1.0 with end deviation 2.0, a descend in place read forward 0.0, a slide read drop 0.0, a small dive read forward 1.0 with drop 0.4, a dive that rose back
read drop 0.0 with end deviation 2.0, and a diagonal dive read sideways 1.5 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
place alone does not prove the dive, a leap does not
prove it, a glide does not prove it, a descend in place does not prove it, a slide does not prove it, a small dive does not prove it, and a dive that rises back does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.65.0 source: the flows battery (all sixty-six
flows plus the anim_dive negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_dive_final.png — the
reference build's red thing at frame 24, in the air
mid-dive at (1.5, 0, 2), halfway down and halfway across.
