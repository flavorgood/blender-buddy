# Blender Buddy v3.48.0 — animation's forty-first piece: dipping

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it dip** sits under "Learn by doing" beside the
modeling, sculpting and first forty animation
pieces — Buddy's forty-first animation piece, teaching
dipping, in four steps:

1. **Pick the thing that will dip** — one thing that will
   drop down toward the ground and come back up.
2. **Remember where it starts, up in the air** — a place
   memory at frame 1, its centre at least 1.7 units up.
3. **Dip it down toward the ground and bring it back up** —
   dipped to about 0.5 units up remembered at frame 24, and
   back at its starting high place remembered at frame 48, in
   its own place sideways the whole way.
4. **Watch it dip, then save** — played across the
   span, and the file saved with the place memories
   in it.

The teaching point is that a dip is the going down
and the coming back together: the float piece sent a thing
up a little and kept it there, and the land piece brought
a thing down and left it there — a dip starts up in the
air, drops toward the ground, and climbs back to the same
high place, reading places 2.0 / 0.5 / 2.0 in height at frames
1/24/48 in the reference build (1.2989 partway down at
frame 12, 1.25 partway back up at frame 36). The checks sample the real evaluated place
across the span: the span must run at least 20 frames,
the start height must land between 1.7 and 2.3, the dip
depth — the start height minus the lowest sampled
height — must land between 1.0 and 1.8, the lowest height
must land between 0.2 and 0.9, the end height must land
within 0.3 of the start height, and the thing must stay
within 0.5 sideways of its start place. A probe on Blender 5.3.0 and 4.2.5
before building showed the place memories at
(0, 0, 2.0), (0, 0, 0.5) and (0, 0, 2.0) across frames
1/24/48 read back and interpolate identically on both
versions (span 47, start 2.0, lowest 0.5, depth
1.5, end 2.0, drift 0.0 in the probe); a hover read depth 0.0
with lowest 2.0, a land read end 0.5, a float read
start 0.0 with depth 0.0, a bob read start 0.0 with
depth 0.0, a small dip read depth 0.4 with lowest 1.6, and
a slide read depth 0.0 with drift 3.0 — all failing the bar.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a high starting
place alone does not prove the dip, a hover does not
prove it, a land does not prove it, a bob does not
prove it, a small dip does not prove it, and a slide
does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.48.0 source: the flows battery (all forty-nine
flows plus the anim_dip negatives), the interface
battery, and the plain-layer and search batteries all
pass. Proof picture: demo/anim_dip_final.png — the
reference build's red thing at frame 24, at the bottom
of its dip, down near the ground in its own place with its
shadow below.
