# Blender Buddy v3.30.0 — animation's twenty-third piece: sliding

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it slide** sits under "Learn by doing" beside the
modeling, sculpting and first twenty-two animation pieces —
Buddy's twenty-third animation piece, teaching sliding, in
four steps:

1. **Pick the thing that will slide** — one thing that will
   glide across the ground.
2. **Remember where it starts, on the ground** — a place
   memory at frame 1, the thing resting on the ground.
3. **Slide it across the ground to a far place** — one long
   flat glide, the far place remembered at the last frame.
4. **Watch it slide, then save it** — played across the
   span, and the file saved with the place memories in it.

The teaching point is that a slide is a journey that stays
flat: the thing really goes somewhere, unlike a shake, but
it never leaves the ground — reading (1.4521, 0, 1) partway
across at frame 24, exactly as high as it started. The
checks read the real evaluated place at the first and last
memories and sample it across the span: the span must run
at least 20 frames, the flat travel at least 2.0 units,
the height at the end within 0.35 of the height at the
start, and the height held within 0.35 the whole way
across. A probe on Blender 5.3.0 and 4.2.5 before building
showed the place memories at (0, 0, 1) and (3, 0, 1)
across frames 1/48 read back and interpolate identically
on both versions (span 47, travel 3.0, height change 0.0,
height variation 0.0 in the probe); a rise read travel
0.0 with height change 3.0, a bounce read travel 0.0 with
height variation 2.0, and a small shuffle read travel
0.5 — all failing the bar.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting place alone
does not prove the slide, a rise does not prove it, a
small shuffle does not prove it, and a bounce does not
prove it either.

Verified on Blender 5.3.0 AND 4.2.5 at the final v3.30.0
source: the flows battery (all thirty-one flows plus
the anim_slide negatives), the interface battery, and
the plain-layer and search batteries all pass on both
versions. Proof picture: demo/anim_slide_final.png —
the reference build's red thing at frame 24, halfway
across its slide, the blue start pad on the ground where
it started.
