# Blender Buddy v3.62.0 — animation's fifty-fifth piece: growing taller

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it taller** sits under "Learn by doing" beside the
modeling, sculpting and first fifty-four animation
pieces — Buddy's fifty-fifth animation piece, teaching
growing taller, in four steps:

1. **Pick the thing that will get taller** — one thing that will
   rise up through its height and stay tall.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Make it taller and keep it tall** —
   height up to 2.0 (Z scale 2.0) remembered at frame 24, i.e. (1, 1, 2), and
   the same taller size remembered again at frame 48, length
   and width staying at 1.0 the whole way.
4. **Watch it grow taller, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a growing taller is the raising
up through one way and the staying and the unchanged length and
width together: the thin piece pulled a thing's
width only, to half its size — a growing taller raises the
height only, to twice its size, keeps it tall, and leaves the length and width
at their own size, reading sizes
(1, 1, 1) / (1, 1, 2) / (1, 1, 2) at frames
1/24/48 in the reference build ((1, 1, 2) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end height ratio (Z) must land between 1.7 and 2.3, the end length and width ratios must each land between 0.8 and 1.2, the
sampled height ratio must never rise above 2.35, and the
sampled length and width ratios must never rise above 1.35 or fall below 0.65. A probe on Blender 5.3.0 and 4.2.5
before building showed the size memories at
(1, 1, 1), (1, 1, 2) and (1, 1, 2) across frames
1/24/48 read back (span 47, end X 1.0, end Y
1.0, end Z 2.0, highest Z 2.0, lowest X 1.0, highest X 1.0, lowest Y 1.0, highest Y 1.0 in the probe); a widen read end X 2.0 with end Y 2.0,
a thicken read end Y 2.0, a lengthen read end X 2.0, a grow read end X 2.5 with end Z 2.5, a shrink read end X 0.4, a crouch read end Z 0.5, a small taller read end Z 1.3, and a taller that returned
read end Z 1.0 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the growing taller, a widen does not
prove it, a thicken does not prove it, a lengthen does not prove it, a grow does not prove it, a shrink does not prove it, a crouch does not
prove it, a small taller does not prove it, and a taller that returns does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.62.0 source: the flows battery (all sixty-three
flows plus the anim_taller negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_taller_final.png — the
reference build's red thing at frame 36, grown taller
to double height with its length and width unchanged, on the
ground.
