# Blender Buddy v3.13.0 — animation's sixth piece: paths

One new guided flow, and nothing else changes.

**Follow a path** sits under "Learn by doing" beside the
modeling, sculpting and first five animation pieces
— Buddy's sixth animation piece, teaching paths, in
five steps:

1. **Pick the thing that will travel** — one traveller
   that will ride the route.
2. **Draw the path it will follow** — a curve whose
   drawn line runs a real distance across the scene
   (the reference route runs 9 units: out, round a
   corner, and on).
3. **Put it on the path** — a Follow Path rule on the
   traveller, aimed at the drawn curve, measuring the
   journey as a share of the whole route (Fixed
   Location).
4. **Remember the journey along it** — the rule's
   Offset remembered at 0 at frame 1 and at the whole
   way (1) at frame 48; the memories live on the rule,
   not on the thing.
5. **Watch it travel, then save it** — played along
   the route, and the file saved with the path, the
   rule and its memories still on it.

The teaching point is the other way animators move
things: instead of remembering places and letting
Blender fill in between them, the route itself is
drawn and the filling-in follows it, corner and all.
The checks read the curve itself (drawn length summed
along its own points), the rule itself (on the
traveller, aimed at that curve, measuring by share),
its Offset memories (span at least 20 frames, at
least half the way travelled), and the traveller's
real world place read across the span — the reference
build's real excursion is 4.21 units, because the
corner carries it farther than the journey's ends
suggest. A probe on Blender 5.3.0 and 4.2.5 before
building showed the rule and its Offset memories read
and ride identically on both versions.

One defect was found and fixed during the build: a
curve created through Blender's data API is not
tagged for evaluation until something tags it — in
the window, operators do that invisibly — so a
headless reference build's Follow Path rule read a
path that was never built and the traveller never
moved. The build now tags the curve plainly when it
draws it, and the evaluated-place read tags the
rule's target curve before reading.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a drawn path alone
does not prove the tie, and a traveller tied to the
path with no travel remembered does not prove the
journey.

Verified on Blender 5.3.0 AND 4.2.5 at the final
v3.13.0 source: the flows battery (all fourteen flows
plus the anim_path negatives), the interface battery,
and the plain-layer and search batteries all pass on
both versions. Proof picture:
demo/anim_path_final.png — the reference build's red
traveller at frame 24, halfway along its drawn route,
on the corner leg of the journey.
