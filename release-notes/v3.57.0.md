# Blender Buddy v3.57.0 — animation's fiftieth piece: narrowing

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it narrow** sits under "Learn by doing" beside the
modeling, sculpting and first forty-nine animation
pieces — Buddy's fiftieth animation piece, teaching
narrowing, in four steps:

1. **Pick the thing that will narrow** — one thing that will
   pull in sideways and stay narrow.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Narrow it and keep it narrow** —
   sides in to 0.5 (X and Y scale 0.5) remembered at frame 24, i.e. (0.5, 0.5, 1), and
   the same narrowed size remembered again at frame 48, height
   staying at 1.0 the whole way.
4. **Watch it narrow, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a narrowing is the pulling in
and the staying and the unchanged height together: the widen piece
spread a thing's sides only while its height stayed at its own height — a narrowing
pulls the sides only, keeps them pulled in, and leaves the height at its own height, reading sizes
(1, 1, 1) / (0.5, 0.5, 1) / (0.5, 0.5, 1) at frames
1/24/48 in the reference build ((0.5, 0.5, 1) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end side ratios (X and Y) must each land between 0.35 and 0.65, the end height ratio must land between 0.8 and 1.2, the
sampled height ratio must never fall below 0.65 or rise above 1.35, and the
sampled side ratios must never fall below 0.3. A probe on Blender 5.3.0 and 4.2.5
before building showed the size memories at
(1, 1, 1), (0.5, 0.5, 1) and (0.5, 0.5, 1) across frames
1/24/48 read back and interpolate identically on both
versions (span 47, end X 0.5, end Y 0.5, end Z
1.0, lowest Z 1.0, highest Z 1.0, lowest side 0.5 in the probe); a shrink read end sides 0.4 and 0.4 with end Z 0.4 and lowest Z 0.4,
a grow read end X 2.5 with end Z 2.5 and highest Z 2.5, a squash read end sides 1.0 and 1.0 with lowest Z 0.4, a small narrow read end sides 0.85 and 0.85, a narrow that returned
read end sides 1.0 and 1.0, a stretch that raised the height read end Z 2.5 with highest Z 2.5, and a narrow along one side only read end Y 1.0 — all failing the bar.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the narrowing, a shrink does not
prove it, a grow does not prove it, a squash does not prove it, a small narrow does not
prove it, a narrow that returns does not prove it, and a stretch does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.57.0 source: the flows battery (all fifty-eight
flows plus the anim_narrow negatives), the interface
battery, and the plain-layer and search batteries all
pass. Proof picture: demo/anim_narrow_final.png — the
reference build's red thing at frame 36, narrowed
to half its width with its height unchanged, on the
ground.
