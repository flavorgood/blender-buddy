# Blender Buddy v3.53.0 — animation's forty-sixth piece: stepping down

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it step down** sits under "Learn by doing" beside the
modeling, sculpting and first forty-five animation
pieces — Buddy's forty-sixth animation piece, teaching
stepping down, in four steps:

1. **Pick the thing that will step down** — one thing that will
   step down and stay there.
2. **Remember where it starts, up high** — a place
   memory at frame 1, centre at 1.0 up, i.e. (0, 0, 1).
3. **Step it down and keep it there** —
   moved 1.0 forward along X and 1.0 down along Z remembered at frame 24, i.e. (1, 0, 0), and
   the same stepped-down place remembered again at frame 48, never
   travelling sideways the whole way.
4. **Watch it step down, then save** — played across the
   span, and the file saved with the place memories
   in it.

The teaching point is that a step down is the forward
step and the drop and the staying together: the step up piece
stepped a thing forward and up together and kept it there in its new higher place — a step down
steps forward AND down, one step in both directions together, and stays in the
new place on the ground, never travelling
sideways and never rising above where it started, reading places
(0, 0, 1) / (1, 0, 0) / (1, 0, 0) at frames
1/24/48 in the reference build (0.4674 forward and 0.5326 up partway
across at frame 12). The checks sample the real evaluated place
across the span: the span must run at least 20 frames,
the forward displacement from the start place to the end
place must land between 0.7 and 1.3, the drop from the start
height to the end height must land between 0.7 and 1.3, the start
height must land between 0.7 and 1.3, the end
height must land between -0.3 and 0.3, on the ground, the sideways drift
along Y must stay within 0.5 across all samples, and the
sampled height must never rise more than 0.35 above the start height. A probe on Blender 5.3.0 and 4.2.5
before building showed the place memories at
(0, 0, 1), (1, 0, 0) and (1, 0, 0) across frames
1/24/48 read back and interpolate identically on both
versions (span 47, forward 1.0, sideways drift
0.0, start 1.0, end 0.0, highest 1.0 in the probe); a step up read forward 1.0 with drop -1.0 and end 1.0,
a step forward read forward 2.0 with drop 0.0, a straight drop read forward 0.0 with drop 1.0, a hop read drop 0.0 with end 1.0, a small step down read forward 0.3 with drop 0.3, a diagonal sidestep-down
read sideways drift 1.0, and a climb read forward 0.0 with drop -2.0 and end 3.0 — all failing the bar.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a high starting
place alone does not prove the step down, a step up does not
prove it, a step forward does not prove it, a straight drop does not prove it, a hop does not prove it, a small step down does not
prove it, a diagonal sidestep-down does not prove it, and a climb does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.53.0 source: the flows battery (all fifty-four
flows plus the anim_stepdown negatives), the interface
battery, and the plain-layer and search batteries all
pass. Proof picture: demo/anim_stepdown_final.png — the
reference build's red thing at frame 36, in its
stepped-down place on the ground with its
shadow below.
