# Blender Buddy v3.12.0 — animation's fifth piece: loops

One new guided flow, and nothing else changes.

**Make it loop** sits under "Learn by doing" beside the
modeling, sculpting and first four animation pieces
— Buddy's fifth animation piece, teaching loops, in
four steps:

1. **Start with a move that travels** — one thing, its
   place remembered at frame 1, moved a clear distance
   and remembered again at frame 48.
2. **Make it repeat for ever** — the Cycles rule on
   every one of the mover's place curves, so when the
   curve runs out it plays again from the start.
3. **Join the ends so it flows** — the last memory is
   the starting place again, reached by a journey out
   to a middle memory and back, so the repeat flows
   instead of jumping.
4. **Watch it loop, then save it** — played through
   the join, and the file saved with the rule and the
   memories still on it.

The teaching point is that a loop is two halves, and
both are checked: repetition (the Cycles rule must be
on ALL of the mover's place curves — one curve left
out would drift while the others repeat) and the join
(the ends must be the same place, with a real journey
in between — read by putting the play line across the
span: the reference build travels 3.16 units out and
comes home, ends exactly together). A probe on
Blender 5.3.0 and 4.2.5 before building showed the
Cycles rule repeats the curve exactly as drawn on both
versions, and the reference build proves it in the
render pass: at frame 72 — a full round past the last
memory — the mover is back out at its far place
(2.98, 0, 0.99), mid-journey in its second round.

One defect was found and fixed during the build: the
first version of the travelling-move check read the
distance between the first and last memories, which a
finished loop reads as zero (its ends are the same
place) — the step unticked itself the moment the loop
was joined. The check now reads the real excursion in
between, the way the join check does.

Negative cases are in the battery alongside the walk:
a plain scene ticks no steps, a travelling move alone
does not prove the repeat, a repeating straight move
does not prove the joined ends, and joined ends
without the repeat rule do not prove the repeat.

Verified on Blender 5.3.0 AND 4.2.5 at the final
v3.12.0 source: the flows battery (all thirteen flows
plus the three new anim_loop negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture:
demo/anim_loop_final.png — the reference build's red
mover at frame 24, out at its far place on the ground,
halfway through its round (one earlier render was
rejected on sight: the mover filled the frame and was
cropped at the edge — the camera was pulled back and
it was re-rendered).
