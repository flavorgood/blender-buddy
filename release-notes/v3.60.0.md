# Blender Buddy v3.60.0 — animation's fifty-third piece: thickening

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it thicken** sits under "Learn by doing" beside the
modeling, sculpting and first fifty-two animation
pieces — Buddy's fifty-third animation piece, teaching
thickening, in four steps:

1. **Pick the thing that will thicken** — one thing that will
   spread out across its width and stay thick.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Thicken it and keep it thick** —
   width out to 2.0 (Y scale 2.0) remembered at frame 24, i.e. (1, 2, 1), and
   the same thickened size remembered again at frame 48, length
   and height staying at 1.0 the whole way.
4. **Watch it thicken, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a thickening is the spreading
across one way and the staying and the unchanged length and
height together: the lengthen piece stretched a thing's
length only, to twice its size — a thickening spreads the
width only, to twice its size, keeps it thick, and leaves the length and height
at their own size, reading sizes
(1, 1, 1) / (1, 2, 1) / (1, 2, 1) at frames
1/24/48 in the reference build ((1, 2, 1) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end width ratio (Y) must land between 1.7 and 2.3, the end length and height ratios must each land between 0.8 and 1.2, the
sampled width ratio must never rise above 2.35, and the
sampled length and height ratios must never rise above 1.35 or fall below 0.65. A probe on Blender 5.3.0 and 4.2.5
before building showed the size memories at
(1, 1, 1), (1, 2, 1) and (1, 2, 1) across frames
1/24/48 read back (span 47, end X 1.0, end Y
2.0, end Z 1.0, highest Y 2.0, lowest X 1.0, highest X 1.0, lowest Z 1.0, highest Z 1.0 in the probe); a widen read end X 2.0 with highest X 2.0,
a grow read end X 2.5 with end Z 2.5 and highest Y 2.5, a lengthen read end X 2.0 with highest X 2.0, a stretch in height read end Z 2.0 with highest Z 2.0, a shrink read end Y 0.4 with lowest X 0.4 and lowest Z 0.4, a small thicken read end Y 1.3, and a thicken that returned
read end Y 1.0 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the thickening, a widen does not
prove it, a grow does not prove it, a lengthen does not prove it, a stretch in height does not
prove it, a shrink does not prove it, a small thicken does not prove it, and a thicken that returns does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.60.0 source: the flows battery (all sixty-one
flows plus the anim_thicken negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_thicken_final.png — the
reference build's red thing at frame 36, thickened
to double width with its length and height unchanged, on the
ground.
