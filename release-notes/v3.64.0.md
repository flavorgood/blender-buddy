# Blender Buddy v3.64.0 — animation's fifty-seventh piece: leaping

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it leap** sits under "Learn by doing" beside the
modeling, sculpting and first fifty-six animation
pieces — Buddy's fifty-seventh animation piece, teaching
leaping, in four steps:

1. **Pick the thing that will leap** — one thing that will
   leave the ground, travel far forward in the air, and
   land far ahead.
2. **Remember where it starts, down on the ground** — a place
   memory at frame 1, location (0, 0, 1).
3. **Leap it up and forward and land it far ahead** —
   mid-leap place (1.5, 0, 3) remembered at frame 24, and
   landing place (3, 0, 1) remembered at frame 48, never
   travelling sideways the whole way.
4. **Watch it leap, then save** — played across the
   span, and the file saved with the place memories
   in it.

The teaching point is that a leap is the leaving the
ground, the far forward travel and the landing back on
the ground together: the slide piece travelled far
across the ground without ever leaving it, and the
bounce piece arced in its own place — a leap leaves the
ground, travels far ahead in the air, and lands back at
its starting height, reading places
(0, 0, 1) / (1.5, 0, 3) / (3, 0, 1) at frames
1/24/48 in the reference build ((2.5375, 0, 2.0) partway down at frame 36). The checks sample the real evaluated place
across the span: the span must run at least 20 frames,
the forward travel must land between 2.2 and 3.8, the peak height must clear at least 1.2 above the start height, the
landing height must sit within 0.35 of the start height, and the
sideways drift must stay within 0.5. A probe on Blender 5.3.0 and 4.2.5
before building showed the place memories at
(0, 0, 1), (1.5, 0, 3) and (3, 0, 1) across frames
1/24/48 read back (span 47, forward 3.0, peak
2.0, ends gap 0.0, sideways 0.0 in the probe); a slide read peak 0.0,
a bounce in place read forward 0.0 with peak 2.5, a glide-like travel read ends gap 1.0, a small leap read forward 1.0 with peak 0.4, a leap that returned
read forward 0.0, and a diagonal leap read sideways 1.5 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
place alone does not prove the leap, a slide does not
prove it, a bounce in place does not prove it, a small leap does not prove it, and a leap that returns does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.64.0 source: the flows battery (all sixty-five
flows plus the anim_leap negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_leap_final.png — the
reference build's red thing at frame 24, up in the air
mid-leap at (1.5, 0, 3), halfway across.
