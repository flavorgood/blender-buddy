# Blender Buddy v3.61.0 — animation's fifty-fourth piece: thinning

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it thin** sits under "Learn by doing" beside the
modeling, sculpting and first fifty-three animation
pieces — Buddy's fifty-fourth animation piece, teaching
thinning, in four steps:

1. **Pick the thing that will get thin** — one thing that will
   pull in across its width and stay thin.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Thin it and keep it thin** —
   width in to 0.5 (Y scale 0.5) remembered at frame 24, i.e. (1, 0.5, 1), and
   the same thinned size remembered again at frame 48, length
   and height staying at 1.0 the whole way.
4. **Watch it thin, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a thinning is the pulling
in across one way and the staying and the unchanged length and
height together: the thicken piece spread a thing's
width only, to twice its size — a thinning pulls the
width only, to half its size, keeps it thin, and leaves the length and height
at their own size, reading sizes
(1, 1, 1) / (1, 0.5, 1) / (1, 0.5, 1) at frames
1/24/48 in the reference build ((1, 0.5, 1) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end width ratio (Y) must land between 0.35 and 0.65, the end length and height ratios must each land between 0.8 and 1.2, the
sampled width ratio must never fall below 0.3, and the
sampled length and height ratios must never rise above 1.35 or fall below 0.65. A probe on Blender 5.3.0 and 4.2.5
before building showed the size memories at
(1, 1, 1), (1, 0.5, 1) and (1, 0.5, 1) across frames
1/24/48 read back (span 47, end X 1.0, end Y
0.5, end Z 1.0, lowest Y 0.5, lowest X 1.0, highest X 1.0, lowest Z 1.0, highest Z 1.0 in the probe); a widen read end X 2.0 with end Y 2.0,
a thicken read end Y 2.0, a grow read end X 2.5 with end Z 2.5, a shrink read end X 0.4, a lengthen read end X 2.0, a stretch in height read end Z 2.0, a small thin read end Y 0.85, and a thin that returned
read end Y 1.0 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the thinning, a widen does not
prove it, a thicken does not prove it, a grow does not prove it, a shrink does not prove it, a lengthen does not prove it, a stretch in height does not
prove it, a small thin does not prove it, and a thin that returns does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.61.0 source: the flows battery (all sixty-two
flows plus the anim_thin negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_thin_final.png — the
reference build's red thing at frame 36, thinned
to half width with its length and height unchanged, on the
ground.
