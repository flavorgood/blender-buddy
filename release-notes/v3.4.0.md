# Blender Buddy v3.4.0 — sculpting's second piece: the mirror

One new guided flow, and nothing else changes.

**Sculpt both sides at once** sits under "Learn by doing" beside
"Sculpt it like clay" — Buddy's second sculpting piece, teaching
symmetry the way sculptors actually use it, in four steps:

1. **Start with fresh clay** — a finer ball than the first flow's,
   because paired features (an eye hollow, a cheek) need the
   points to read in.
2. **Work one side — the mirror works the other** — turn the X
   symmetry on, then block the big paired forms working one side
   only. The step ticks only when the surface itself proves the
   mirror was in effect: the checks read the clay against its own
   mirror image, and work done without the mirror does not tick
   it, however careful it looks from the front.
3. **Break the mirror on purpose** — symmetry off, and a little
   small, late, one-sided life (one brow higher, one cheek
   fuller), because real faces are not mirror images. The tick
   reads a surface whose big forms still match side to side,
   carrying real one-sided work on top.
4. **Smooth finish, then save** — smooth shading and the file
   saved, with the sides still matching.

Negative cases are in the battery alongside the walk: a plain
untouched ball ticks only step 1, and big one-sided work done
without the mirror does not prove step 2.

The Start screen's coverage box now names both sculpting pieces
and still says plainly that they are a first piece of the craft,
not the whole of it; animation and the other crafts remain
untaught. DynTopo, masks/face sets and Multires are still not
taught — they are the later sculpting pieces, in that order.

Verified on Blender 5.3.0: the flows battery (all five flows
walked end to end, sculpt_symmetry included, plus its two
negative cases), the interface battery (including the coverage
box), and the plain-layer and search batteries. test_context
fails at its Codex-availability assertion in this environment —
confirmed identical on the untouched v3.3.0 baseline, so it is
an environment gap (no Codex program here), not a change in
this version. The 4.2.5 binary was not present on the build
machine this run, so the 4.2.5 pass is still owed; the full
parallel battery (test_tour) remains owed on an unloaded
machine, as recorded in the lane queue.
