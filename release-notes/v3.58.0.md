# Blender Buddy v3.58.0 — animation's fifty-first piece: lengthening

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it lengthen** sits under "Learn by doing" beside the
modeling, sculpting and first fifty animation
pieces — Buddy's fifty-first animation piece, teaching
lengthening, in four steps:

1. **Pick the thing that will lengthen** — one thing that will
   stretch out along its length and stay long.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Lengthen it and keep it long** —
   length out to 2.0 (X scale 2.0) remembered at frame 24, i.e. (2, 1, 1), and
   the same lengthened size remembered again at frame 48, width
   and height staying at 1.0 the whole way.
4. **Watch it lengthen, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a lengthening is the stretching
along one way and the staying and the unchanged width and
height together: the widen piece spread both sides only
while its height stayed at its own height, and the narrow
piece pulled both sides in — a lengthening stretches the
length only, keeps it long, and leaves the width and height
at their own size, reading sizes
(1, 1, 1) / (2, 1, 1) / (2, 1, 1) at frames
1/24/48 in the reference build ((2, 1, 1) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end length ratio (X) must land between 1.7 and 2.3, the end width and height ratios must each land between 0.8 and 1.2, the
sampled length ratio must never rise above 2.35, and the
sampled width and height ratios must never rise above 1.35 or fall below 0.65. A probe on Blender 4.2.5
before building showed the size memories at
(1, 1, 1), (2, 1, 1) and (2, 1, 1) across frames
1/24/48 read back (span 47, end X 2.0, end Y
1.0, end Z 1.0, highest X 2.0, lowest Y 1.0, highest Y 1.0, lowest Z 1.0, highest Z 1.0 in the probe); a widen read end Y 2.0 with highest Y 2.0,
a grow read end X 2.5 with end Z 2.5 and highest X 2.5, a shrink read end X 0.4 with lowest Y 0.4 and lowest Z 0.4, a stretch in height read end Z 2.0 with highest Z 2.0, a small lengthen read end X 1.3, a lengthen that returned
read end X 1.0, and a width-only widen read end X 1.0 with end Y 2.0 — all failing the bar. The probe ran on Blender 5.3.0 and 4.2.5 with byte-identical outputs.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the lengthening, a widen does not
prove it, a grow does not prove it, a shrink does not prove it, a stretch in height does not
prove it, a small lengthen does not prove it, a lengthen that returns does not prove it, and a width-only widen does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.58.0 source: the flows battery (all fifty-nine
flows plus the anim_lengthen negatives), the interface
battery, and the plain-layer and search batteries all
pass on both versions. Proof picture: demo/anim_lengthen_final.png — the
reference build's red thing at frame 36, lengthened
to twice its length with its width and height unchanged, on the
ground.
