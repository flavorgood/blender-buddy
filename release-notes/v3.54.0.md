# Blender Buddy v3.54.0 — animation's forty-seventh piece: crouching

One new guided flow, and nothing else changes. Built and
held locally under the owner's 2026-11-26 release-batching
rule — this is batch bookkeeping, not a separate release;
it ships together with the first batched release.

**Make it crouch** sits under "Learn by doing" beside the
modeling, sculpting and first forty-six animation
pieces — Buddy's forty-seventh animation piece, teaching
crouching, in four steps:

1. **Pick the thing that will crouch** — one thing that will
   lower down and stay crouched.
2. **Remember its starting size** — a size
   memory at frame 1, at its own shape, i.e. scale (1, 1, 1).
3. **Crouch it down and keep it crouched** —
   height down to 0.5 (Z scale 0.5) remembered at frame 24, i.e. (1, 1, 0.5), and
   the same crouched size remembered again at frame 48, sides
   staying at 1.0 the whole way.
4. **Watch it crouch, then save** — played across the
   span, and the file saved with the size memories
   in it.

The teaching point is that a crouch is the lowering
and the staying and the unchanged sides together: the squash piece
flattened a thing down while its sides bulged out and then let it settle back to full height — a crouch
lowers the height only, keeps it lowered, and stays in the
crouched size, its sides never changing, reading sizes
(1, 1, 1) / (1, 1, 0.5) / (1, 1, 0.5) at frames
1/24/48 in the reference build ((1, 1, 0.5) again at frame 36). The checks sample the real evaluated size
across the span: the span must run at least 20 frames,
the end height ratio (end Z over start Z) must land between 0.35 and 0.65, the end
side ratios (X and Y) must each land between 0.8 and 1.2, and the
sampled height ratio must never rise above 1.15. A probe on Blender 5.3.0 and 4.2.5
before building showed the size memories at
(1, 1, 1), (1, 1, 0.5) and (1, 1, 0.5) across frames
1/24/48 read back and interpolate identically on both
versions (span 47, end height 0.5, end sides
1.0 and 1.0, highest 1.0 in the probe); a squash read end height 1.0,
a shrink read end sides 0.4 and 0.4, a stretch read end height 2.0 with highest 2.0, a small crouch read end height 0.85, and a crouch that recovered
read end height 1.0 — all failing the bar.

Negative cases are in the battery alongside the walk:
a plain scene ticks only step 1, a starting
size alone does not prove the crouch, a squash does not
prove it, a shrink does not prove it, a stretch does not prove it, a small crouch does not
prove it, and a crouch that recovers does not prove it either.

Verified on Blender 5.3.0 and 4.2.5 at the final
v3.54.0 source: the flows battery (all fifty-five
flows plus the anim_crouch negatives), the interface
battery, and the plain-layer and search batteries all
pass. Proof picture: demo/anim_crouch_final.png — the
reference build's red thing at frame 36, crouched
at half height with its sides unchanged, on the
ground.
